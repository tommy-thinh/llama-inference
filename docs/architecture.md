# Architecture and security

The browser sends requests to FastAPI, which communicates with a separate CPU-only llama-server and streams tokens back as server-sent events (SSE). Keeping inference separate allows the model to remain loaded while the backend handles sessions, persistence, admission and cancellation. In the intended public topology Caddy serves the static frontend and proxies the API over loopback; the private local workflow uses FastAPI to serve both.

The application uses a single backend worker. PostgreSQL holds anonymous sessions, conversations, messages, requests and durable daily quota reservations. A random HttpOnly, SameSite=Lax cookie identifies a session; the database stores its hash. Clearing the cookie loses access to the associated conversations. A copied cookie grants its holder access: this is anonymous ownership, not an account system.

A turn is reserved transactionally before generation. Streaming happens outside the transaction, with periodic partial-text checkpoints. Completion is committed before the terminal event; cancellation and failure preserve the latest durable partial text. Startup marks interrupted requests failed. The single-worker constraint matters because recovery and the in-memory admission queue have one owner. Multiple workers would require a different coordination design.

The API validates input and provides persistent conversation operations and streaming. The public profile requires an exact HTTPS origin and Secure cookies, checks Host, Origin and Fetch Metadata, disables the transient chat endpoint and API docs, bounds requests and tracks rate limits. The default admission policy has one active generation and two FIFO waiters; saturation returns 503 with Retry-After. Daily request and reserved-output-token quotas persist in PostgreSQL, while short-window limits reset on process restart. Reservations are conservative and are not refunded for cancelled or failed requests.

Caddy overwrites the trusted client-IP header; this trust model assumes direct connections through that proxy. Do not put another proxy in front without revisiting it. Loopback limits network exposure but is not authentication between local users; use a trusted single-tenant host. Rate limits and quotas do not provide content filtering or volumetric attack protection. Public deployment, service limits and external firewall behavior require the checks in [deployment](deployment.md); [operations](operations.md) covers backup, recovery and troubleshooting.
